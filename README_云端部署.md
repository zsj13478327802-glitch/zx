# ZX AI Commerce Studio · 云端部署版 v0.2

## 当前状态

这是**可部署的云端程序源码**，而不是已经上线的网站。只有在用户连接并授权使用云部署平台、创建服务并完成发布后，才会产生可以直接访问的 HTTPS 公网网址。

## 推荐 Railway 部署

1. 建立**私有** GitHub 仓库，并上传此目录（不要上传 `.env` 或 `data/` 里的用户商品文件）。
2. 打开 Railway，将 GitHub 仓库作为新服务的代码来源。平台会自动识别仓库根目录的 `Dockerfile`。
3. 在服务 **Variables** 设置：
   - `ZX_ACCESS_PASSWORD`：12位以上、唯一且保密的工作台访问密码（必填）。
   - `OPENAI_API_KEY`：你自己的 OpenAI API 密钥（仅使用演示背景可以不填）。
   - 可选：`ZX_MAX_AI_IMAGES_PER_JOB=30`、`ZX_MAX_UPLOAD_MB=160`。
4. 为服务添加持久化 **Volume** 并设置 Mount Path 为 `/app/data`。如跳过此步骤，容器重启或重新部署后任务与图片可能丢失。
5. 在 Railway 的 Networking / Public Networking 中生成一个 HTTPS 域名。
6. 通过这个网址打开页面，先用 `ZX_ACCESS_PASSWORD` 登录，再导入少量商品使用演示模式测试；确认结果后再启用 AI。
7. 建议把域名交给同事；不要共享 API 密钥。共享账户/多人精细权限尚未实现。

## 资源和费用

服务器的 CPU、内存、磁盘和出站流量可能计费，AI 模型调用也会按使用单独收费。API 密钥不是 ChatGPT 会员权益。上云之前务必检查预计支出与额度。

## 内置安全措施和限制

- 服务器启动时强制要求 `ZX_ACCESS_PASSWORD` 至少12位；无密码不能在公网启动。
- 默认单口令登录、HttpOnly Secure Cookie，有效期7天，登录错误有次数限制。
- 上传文件校验和ZIP文件大小限制；默认每次上载总量160MB。
- 默认每次AI生产不超过30张，必要时通过服务变量手动提高。
- 访问原始商品图、生成结果和下载接口必须先登录。
- `OPENAI_API_KEY` 只在服务器环境变量中配置，不能放在网页表单或公开的 GitHub 代码。
- 这是单团队私有试用版本，尚无多人独立账号、审计、磁盘清理、对象存储、持久数据库、配额账单、完整安全审计；不要直接作为面向陌生公众的SaaS服务开放。

## 测试策略

先上传3-10张透明PNG或干净白底商品图，检查生成背景、字体、LOGO和包装完整性后再扩大规模；复杂背景的原图可能需要额外抠图。线上AI模式尚需真实密钥和外网环境验收。
